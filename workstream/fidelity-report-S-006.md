## Human-readable summary

This story closes wave 1 with three things. First, a test now walks every prompt file in the three platform trees and the `docs/` folder and fails if any of them ever tells an agent to write to the GitHub Project board — the promise "no agent writes Project Status" is now enforced, not just stated. I confirmed this by dropping a fixture file containing the forbidden command into `.kiro/`: the test failed naming the file and line, and passed again once the fixture was removed. Second, the small corrections raised by the five earlier audits (a wording reason in the label rules, a template for the top-level tracking issue, a pointer instead of a restated title form, two extra gate fields in the status-comment template, a wording fix for Copilot and Kiro, a more precise test helper) were applied identically in all trees, each pinned by a test. Third, the Project setup runbook was corrected from the owner's live exercise (Project 5): the auto-close workflow ships on, either board template is fine, there is no "item reopened" workflow, and deleting the extra fields is optional. I checked Project 5 directly: all seven workflows are enabled and the extra fields are present, as the runbook now says. `TESTING.md` records which live issue proved each behavioural criterion; I re-read every one of those issues and the numbers and comment ids match.

One thing to fix, outside the story's own deliverables: the user-stories file's new changelog row says two acceptance criteria (S-004 AC-1, S-005 AC-3) were updated, but the file's text was not actually changed — only the changelog row was added. The PRD and spec write-backs are correct and consistent with the decisions. Everything else found is minor housekeeping (stale PR body text, old AC wording on two GitHub issues, a cosmetic count in a status comment, the roadmap row the planner updates at the end).
