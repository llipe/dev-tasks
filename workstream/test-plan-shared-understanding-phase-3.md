## A Note on This Phase's Testable Surface

Phase 2's plan had to say that most of its scope was prompt content with no unit-testable runtime. **Phase 3 is the opposite split, and this plan reflects it honestly:**

- **Real code, conventionally testable (S-001, S-002, S-003's check, S-005's check, S-006's fixture):** `core/checks/glossary.ts` with four exported functions (`checkGlossaryContent`, `checkGlossary`, `checkVocabularySection`, `checkExportedIdentifiers`), `checkGlossaryPresence()` in `doctor.ts`, one `INSTALL_IF_ABSENT_FILES` entry, two manifest paths, `run.ts` wiring, and this repository's own populated glossary. These get **unit (`UT-*`)** and **integration (`IT-*`)** cases with deterministic pass/fail, plus **contract (`CT-*`)** assertions on the exported signatures, the file schemas, and the registry shape. This is the bulk of the plan and where the developer's test-first work lands.
- **Prompt content (S-003's skill edits, S-004, S-005's `verifier` edits, S-006's `activity-init` sentence):** covered exactly as Phase 2 covered it — **parity tests (`PT-*`)** for deterministic three-tree presence/absence of required markers, and **hand-walked scenario fixtures (`FX-*`)** in `test/fixtures/grilling/` for the behavioral contract (the FR-21 conflict question, the approval append). No transcript runner is introduced (`SIMPLICITY.md` A4, D-48/D-49 precedent).
- **E2E scenarios (`E2E-*`)** span both halves: the vocabulary lifecycle (WHAT-phase proposal → conflict question → PRD approval → glossary append → `lint` pass) and the install → `doctor` → `lint` path on a fresh consumer. The lifecycle steps that are code (`lint`, `doctor`, `install`) are executable; the steps that are agent behavior are fixture-walked. Each E2E row says which is which.

A test in this plan is either executable (`UT`, `IT`, `CT`, `PT`, `RT`) or walked (`FX`, the agent steps of `E2E`). Nothing walked is reported as executed.
