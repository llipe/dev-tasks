# Compliance Test Plan — infra-engineer

**Status:** Design complete — test-first implementation required  
**Scope:** Task 0 and Stories S-001–S-010; GitHub issues #153–#163  
**Sources:** `docs/requirements/prd-infra-engineer.md` v1.3; `workstream/specification-infra-engineer.md` v1.0; `workstream/user-stories-infra-engineer.md` v1.1; `workstream/tasks-infra-engineer-plan.md`  
**Companion:** `workstream/traceability-matrix-infra-engineer.md`

## Verdict / implementation entry criteria

The scope is testable without adding dependencies. Implementation MUST begin by creating the listed deterministic tests, observing each fail for the intended missing behavior, then implementing only enough to make the relevant test pass. All acceptance criteria have positive and negative/edge coverage in the traceability matrix.

No cloud mutation is authorized by this plan. Manual scenarios use throwaway, non-production resources and require the human approvals already specified by the agent contract. Do not use production credentials, real secret material, or destructive tests against shared environments.

## Test environment and fixtures

- **Repository fixture:** fresh clone/worktree with no uncommitted files, plus fixtures that intentionally contain a template-status `infra/environments.yaml`, a populated non-production environment, and an ambiguous multi-platform environment.
- **CLI stubs:** `test/fixtures/infra/bin/{aws,flyctl,supabase,yq,gh}` prepend to `PATH`, record argv to a fixture log, return selected statuses, and never contact a provider.
- **Synthetic secrets only:** key-shaped strings from S-005 fixtures; no live tokens, emails, account IDs, database URLs, or cloud output.
- **Throwaway manual target:** non-production Fly organization/app with a typed destruction path; no shared database, production app, or production DNS zone.
- **Environment evidence:** record OS, Node/pnpm versions, command, commit SHA, test seed (where applicable), and sanitized output. Redact before recording.

## Seeded randomized/property tactics

These tactics are supplementary; deterministic fixtures remain the release gate. Seeds MUST be emitted in failure output and recorded with OS/runtime/config. Re-run the exact failing case before triage, maximum three attempts; shrink input and classify defect/spec-gap/flaky according to verifier policy.

| ID    | AC(s)                  | Tactic / input surface                                                                                          | Property/oracle                                                                                                                            | Iterations            | Replay / shrink                                                                                                                       |
| ----- | ---------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| RT-01 | S-005 AC-1–AC-4        | Fuzz secret-shaped and benign log lines: prefixes, casing, separators, JSON quoting, two tokens/line            | Supported secrets never survive; benign corpus is unchanged; output never contains the original supported secret substring                 | 1,000                 | `pnpm run test:unit -- infra-redaction --seed=<seed> --iterations=1`; shrink by removing tokens/characters until minimal leaking line |
| RT-02 | S-001 AC-3–AC-5        | Stateful random walk of planned step metadata/statuses                                                          | Only legal lifecycle transitions occur; production stateful steps have backup before apply; empty production revert never applies          | 500 paths × ≤12 steps | `pnpm run test:unit -- infra-lifecycle --seed=<seed> --iterations=1`; delta-debug action sequence                                     |
| RT-03 | S-008 AC-3–AC-8        | Fuzz script args, environment names, platform block combinations, ref/CI state against stubs                    | No invalid input causes provider stub write; documented blocked inputs return 2 and verify failures 3; dry-run never invokes write argv    | 500                   | `pnpm run test:unit -- infra-script-contract --seed=<seed> --iterations=1`; shrink argv and YAML to smallest case                     |

Seed format: `<tactic>-<story-or-ac>-<unix-timestamp>-<hex4>`. Example: `fuzz-S005-1760000000-a3f1`.

## Manual execution checklist

- [ ] Create a fresh, non-production throwaway Fly target and filled environment file; do not use real secret values.
- [ ] Invoke infra-engineer for a plan; verify plan approval and exactly one step prompt at a time.
- [ ] Exercise a blocked template-status file, wrong identity, missing revert, and missing production backup before any allowed write.
- [ ] Execute and verify a reversible Fly plan; force health-check failure and follow the printed rollback instruction; remove target resources.
- [ ] Dry-run AWS IAM policy attach and inspect generated revert without applying it.
- [ ] On non-production Supabase, produce a `db diff` containing `DROP`; confirm itemization and no push before explicit human confirmation. Do not apply destructive SQL unless separately approved.
- [ ] In a Claude-agent session, attempt a prohibited tag command and observe the hook refusal.
- [ ] Scratch-install then update a consumer repo; verify filled `infra/environments.yaml` and consumer deploy workflow are unchanged.
- [ ] Give developer a shared-production-secret task and observe handoff to infra-engineer; give developer an `.env.example` task and observe it remains local.

## Completion criteria

1. Every matrix row has a passing positive and negative/edge result, or is explicitly `blocked` with missing evidence.
2. All deterministic commands in the execution order pass, including `pnpm run test`, `pnpm run validate`, and `pnpm run audit`.
3. `coverage_gate` is recorded by qa-engineer as `PASS`, `FAIL`, or `SKIPPED(<reason>)`.
4. A verifier Audit Mode run compares implementation, workstream artifacts, tests, and intended behavior before PR readiness.
5. Manual evidence is sanitized and links to the relevant issue/PR; cloud resource cleanup is evidenced.
