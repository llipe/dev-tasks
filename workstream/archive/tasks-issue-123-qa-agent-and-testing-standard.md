## Context

- **Source of scope:** `workstream/issue-123-qa-agent-and-testing-standard-refinement.md` (v1.0), refined from GitHub Issue [#123](https://github.com/llipe/dev-tasks/issues/123). AC-1 through AC-9 in that document are the authority for this task list.
- **Existing codebase, not greenfield:** no Task 0. This repo already has `package.json`, vitest, ESLint, Prettier, and `test/unit` + `test/integration` suites.
- **Quality gates:** this repo now has canonical scripts. Use `pnpm run test:unit`, `pnpm run test:integration`, `pnpm run validate` (typecheck + lint + format:check + test), and `./scripts/format.sh --check` for Markdown. The framework-repo exception in the refinement means this issue does **not** add missing scripts (`test:e2e`, `test:coverage`) to this repo's own `package.json`.
- **Migration lifecycle tasks — documented opt-out:** no schema or data-model changes are in scope. The deliverables are Markdown agent/skill/contract files plus small TypeScript/shell distribution wiring. No database exists.
- **Test-first:** sub-tasks 1.2-1.3 author the failing structural tests before any agent, skill, or contract file is created, per `developer` rule 19 and the repository's test-first default.
- **Distribution note discovered during planning:** `/DESIGN.md` is not distributed to consumer repos at all — it is repo-local. `/TESTING.md` must reach consumer repos because cross-project standardization is the point of this issue (AC-10), so it follows the `AGENTS.md`/`CLAUDE.md` pattern instead: listed in `MANAGED_FILES` (shipped) **and** in `consumer_owned_paths` (never overwritten on update). Both distribution paths need work: the shell bundle (`scripts/build-bundle.sh`) is a simple list addition, but the npm installer is not — `core/distribution/install.ts` iterates `PROFILE_PATHS` per platform and tags every installed file with a `profile`, so a platform-agnostic root file fits neither shape. Implementation must decide how a root file is tagged in the manifest and must avoid installing it three times under `--profile all`.
- **Reference case:** the five additions in v1.2 come from a real test audit of the `home-ledger` repository. That audit is the acceptance benchmark — the delivered skills must be able to detect its findings: an aggregate test script omitting a package with 393 tests while every script name is canonically correct, a deploy quality gate that never runs backend tests, no coverage provider installed anywhere, a stale coverage artifact measuring 1 of 8 modules, a React Native app tested under `environment: 'node'`, missing test configs and alias mismatches, `expect(true)` placeholders reporting false health, auth tests that pass `alg: 'none'` tokens because the implementation never verifies signatures, and a mixed vitest + pytest monorepo.
- **Prompt-length target:** AC-2 caps the Kiro `qa-engineer` prompt at 150 lines. For reference, `.kiro/agents/verifier.md` is ~280 lines. Keeping the QA agent short is an explicit acceptance criterion, not a stylistic preference. The five v1.2 additions land in the **skills**, not the agent prompt, so the cap stays achievable.
