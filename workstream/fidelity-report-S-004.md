## 1. Human-readable summary

The developer agent is the role that builds one story at a time. When it finishes, it hands a short closeout block to whoever asked for the work (usually the planner). This story adds two lines to that block: whether the story's progress comment on its GitHub issue was kept up to date, and whether the wave-level comment was updated or left to the planner. The planner already reads that block, so the new information arrives where it is already looked for.

The story also fixes a wording problem. The old rule told the developer to close the issue "after the PR is approved and merged", which is ambiguous when a story merges into an integration branch first. The new rule says the developer never closes the issue; GitHub closes it when the final consolidated PR reaches `main`. And rather than repeating how to write the progress comment, the developer's rules now point to the one place that procedure lives (the `implement` skill), so there is one copy to maintain.

All of this was applied the same way to the three platform copies of the developer agent (Claude, Copilot, Kiro), tests were written first and seen failing before the edits, and the interactive `/developer` command needed no change because it inherits from the agent file. The story's own issue (#273) was used as a live trial of the progress-comment rule and behaved as specified.
